# tablet 앱 테스트 가이드

의료진용 태블릿 앱을 **개발 환경 없이** 테스트하는 방법.
Flutter 설치 없이 APK만 받아 설치하면 된다.

---

## 1. 설치

### APK 받기

빌드하는 사람이 아래를 실행해 `app-release.apk` (약 69MB)를 만들어 전달한다.

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://medai-backend-XXXXXXXXXX.asia-northeast3.run.app
```

산출물: `tablet/build/app/outputs/flutter-apk/app-release.apk`

> ⚠️ `--dart-define` 을 빠뜨리면 앱 기본값(같은 주소)으로 빌드된다. 다른 서버를 보게
> 하려면 이 값을 바꾼다. **APK에 주소가 박히므로 서버가 바뀌면 다시 빌드해야 한다.**

### 기기에 넣기

**실기기 Android 태블릿을 권한다.** 아래 두 기능은 에뮬레이터로 확인할 수 없다.

| 기능 | 에뮬레이터 |
| --- | --- |
| 이미지 **핀치 확대** | ❌ 마우스로 두 손가락 제스처 불가 (더블탭으로 대체 확인 가능) |
| **QR 스캔** | ❌ 카메라 없음 |

```bash
adb install -r app-release.apk
```

또는 APK 파일을 기기로 복사해 파일 관리자에서 실행한다.
`출처를 알 수 없는 앱` 설치를 허용해야 한다.

- 최소 Android 6.0 (minSdk 23)
- 서명이 개발용이라 Play 스토어 배포용이 아니다. 사내 테스트 전용

## 2. 계정

서버에 역할별 계정이 있다. **비밀번호는 백엔드 담당자에게 받는다.**

| 아이디 | 역할 | 부서 | 이 계정으로만 되는 것 |
| --- | --- | --- | --- |
| `doctor1` | admin | imaging | 계정 신청 승인/거부 |
| `doctor_1234` | doctor | 내과 | **판정 확정** |
| `test_doctor1` | doctor | internal_medicine | **판정 확정** |
| `prodnurse1` | nurse | — | 공유 대상으로 지정할 때 씀 |

> **로그인 필드는 이메일이 아니라 아이디(`username`)다.**

**최소 두 계정이 필요하다.** `admin` 하나로는 판정 확정을 테스트할 수 없다
(서버가 `role=doctor` 만 허용한다).

## 3. 테스트 데이터

서버에 이미 들어 있는 것들이다. 배치 ID 앞 8자리로 찾으면 된다.

| 배치 | 용도 |
| --- | --- |
| `e9ef060b` | **판정 유보(ABSTAIN)** — 확정 버튼, 공유 차단 확인 |
| `d68acf73` | 결과·마스크 정상 + **공유 1건 있음** — 공유 현황 확인 |
| `e73697ec` | **공유받은 배치** — 공유/삭제/공유현황이 막히는지 확인 |
| `81025fa2` | **실패한 배치** — 에러 표시 확인 |
| `865a751c`·`67033c0e` 외 | 결과·마스크 정상 (총 8건) |

환자는 5명 있다. 검색 테스트에 쓴다.

| 차트번호 | 이름 | 생년월일 |
| --- | --- | --- |
| `PE56EA6F7` | Prod Patient | 1990-01-01 |
| `P020753D4CD11` | Seo | 1998-01-01 |
| `PD41D319D6484` | 테스트환자 | 1995-05-05 |

## 4. 시나리오

### 4-1. 로그인

- [ ] 아이디·비밀번호로 로그인 → 대시보드
- [ ] 틀린 비밀번호 → `아이디 또는 비밀번호가 올바르지 않습니다`
- [ ] 앱을 완전히 종료 후 재실행 → **로그인 화면을 건너뛰고 대시보드** (토큰 유지)
- [ ] 로그아웃 → 재실행 시 로그인 화면
- [ ] `신규 계정 신청` → 이름·이메일·직군 입력 → 접수 안내
      (실제로 넣으면 관리자에게 알림이 가고 대기 목록에 쌓이니 협의 후)

### 4-2. 대시보드

- [ ] 배치 목록 18건이 뜬다
- [ ] 필터 `전체 / 진행중 / 완료 / 에러 / 공유` 가 각각 걸린다
- [ ] `공유` → `e73697ec` 1건만. 카드에 공유 아이콘이 붙어 있다
- [ ] 검색창에 `P` → 차트번호로 걸러진다
- [ ] 카드를 누르면 URL이 바뀌며 우측 패널이 채워진다 (대시보드가 겹치지 않는다)
- [ ] 조직 구성 막대 5개가 **서로 다른 색** (종양이 가장 진함)

### 4-3. 판정 유보 확정 — **doctor 계정 필요**

- [ ] `e9ef060b` 선택 → 노란 **판정 유보** 배너
- [ ] `admin` 계정: `판정 확정` 버튼이 **비활성**
- [ ] `doctor` 계정: 버튼 활성 → LOW/HIGH 선택 + 사유 입력 → 확정
- [ ] 사유를 비우면 확정 버튼이 눌리지 않는다
- [ ] 확정 후 요약에 `판정 ABSTAIN` **아래** `확정 LOW — 사유` 가 함께 남는다
      (원본 추론값을 덮지 않는다)

### 4-4. 공유

- [ ] `d68acf73`(내 배치) → `공유` → 직원 선택 + **소견 입력**(200자) → 공유
- [ ] `공유 현황 (n)` 에 소견이 함께 보인다
- [ ] `회수` → 취소선으로 남는다 (물리 삭제가 아니다)
- [ ] `e73697ec`(공유받은 배치) → 공유·삭제·공유현황이 **모두 비활성**, 툴팁에 이유
- [ ] `e9ef060b`(유보) → 공유가 **비활성**, 확정하면 풀린다

### 4-5. 리포트 · 이미지

- [ ] `상세 리포트 열기` → 좌우 2단 (좁으면 상하)
- [ ] 왼쪽에서 **두 손가락 핀치**로 확대 (실기기)
- [ ] **더블탭** → 100% → 200% → 400% → 100%. 탭한 지점이 제자리에 남는다
- [ ] 확대 상태에서 투명도 슬라이더를 움직여도 **두 장의 정렬이 유지**된다
- [ ] 슬라이더 0 = 원본만, 1 = 마스크만
- [ ] 오른쪽에 판독 소견·AI 의견·구성비 요약·**면책 문구**
- [ ] 대시보드 우측 패널의 썸네일을 탭 → 전체화면 뷰어

### 4-6. 새 분석

- [ ] `+ 새 분석` 또는 사이드바 `새 분석`
- [ ] `차트번호` 로 `P` → 여러 명
- [ ] `이름+생년월일` 로 `Prod Patient` + `1990-01-01` → 1명
- [ ] 이름만 입력 → 검색이 돌지 않고 안내만 (오류가 뜨면 안 된다)
- [ ] 부분 이름 `Prod` + 생년월일 → **0건** (정확 일치만 됨)
- [ ] 환자를 고르면 **검색 결과 목록이 사라진다**
- [ ] `샘플 이미지로 테스트` → `분석 시작` → 진행 로그
- [ ] 선택한 채 다른 화면으로 이동 → **경고 다이얼로그**
- [ ] `나가기` 후 다시 들어오면 선택이 비어 있다

### 4-7. 알림

- [ ] 사이드바 알림 벨에 안읽음 배지
- [ ] 알림함에서 `전부 읽음 (n)` → 배지가 사라진다
- [ ] 알림을 누르면 해당 배치로 이동한다
- [ ] 로그인 직후 **알림 권한 팝업**이 뜬다 (Android 13+)
- [ ] 서버가 테스트 푸시를 쏘면 앱이 떠 있을 때/꺼져 있을 때 모두 도착한다

### 4-8. 테마

- [ ] OS를 다크 모드로 → 앱이 따라 바뀌고 **글자가 전부 읽힌다**
- [ ] 조직 구성 막대가 다크에서도 모두 보인다

## 5. 지금은 확인할 수 없는 것

테스터가 "고장"으로 오해하지 않도록 미리 알린다.

| 항목 | 이유 |
| --- | --- |
| **새 분석이 `진행중`에서 멈춤** | GPU 워커가 돌지 않는다. 현재 9건이 이 상태다. **앱 문제가 아니다** |
| **푸시 알림 (조건부)** | 앱 쪽은 준비됐다 — Firebase 설정(`model-platform-502402`)이 APK에 들어 있고, 로그인하면 FCM 토큰을 서버에 등록한다. **서버가 실제로 발송하는지는 받아봐야 안다.** 게다가 지금은 분석이 완료되지 않아 완료 알림을 유발할 수 없다. 서버 담당자에게 테스트 발송을 요청하는 게 확실하다. 인앱 알림함은 무관하게 정상 동작 |
| **QR 스캔** | 환자 앱이 있어야 QR 토큰을 만들 수 있다. 카메라 화면과 오류 처리까지만 확인 가능 |
| **채팅** | 서버가 Firestore로 방향을 정했고 스키마 문서가 아직 없다. 사이드바에서도 뺐다 |
| **진단서 발급** | 서버 API가 없다 |
| **원본 이미지가 안 뜨는 배치** | GCS에 객체가 없는 오래된 데이터다. `d68acf73` 등 8건은 정상 |

## 6. 문제가 보이면

증상과 함께 아래를 같이 주면 원인을 빨리 좁힐 수 있다.

- **배치 ID 앞 8자리** (화면 카드에 `배치 xxxxxxxx` 로 보인다)
- 로그인한 **계정 아이디와 역할**
- 화면 사진
- 기기 종류 (실기기 / 에뮬레이터)

서버가 자주 바뀐다. 앱이 갑자기 이상해지면 **APK를 다시 받아** 확인하는 게 먼저다.
